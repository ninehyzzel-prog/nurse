# 아키텍처 및 도메인 결정 기록 (DECISION_LOG)

> 상태: **Phase 0 확정 v0.1** · 프로젝트 시작 결정 기록

---

## D-01: 기술 스택 선정 (Vite React 19 SPA + FastAPI + SQLite/PostgreSQL)
- **결정:** 프론트엔드는 React 19 + TypeScript + Vite, 백엔드는 Python 3.12 + FastAPI + SQLAlchemy 2.0 + Alembic, 최적화 엔진은 Google OR-Tools CP-SAT을 채택한다.
- **근거:** MASTER_PROMPT §6-1 권장 사양 준수. 빠른 로컬 개발 및 강력한 제약 최적화 생태계(Python OR-Tools)와의 유기적 통합. 로컬 환경에 PostgreSQL이 없으므로 개발은 SQLite, 배포는 PostgreSQL 호환 스키마로 진행.

## D-02: 스타일링 솔루션 선정 (CSS Variables + CSS Modules)
- **결정:** Tailwind CSS 대신 순수 CSS Variables 토큰 + CSS Modules를 채택한다.
- **근거:** MASTER_PROMPT §4 권장 사항 준수. 동적으로 변경될 수 있는 사용자 정의 교대 근무 색상 토큰(CSS Variable)을 컴포넌트 레벨에서 직접 제어하기에 용이하고 종속성을 최소화함.

## D-03: 시간 데이터 모델의 이중화 (UTC Instant + Local Date)
- **결정:** 모든 배정 레코드는 `start_at_utc`, `end_at_utc`와 함께 `local_start_date`를 독립 컬럼으로 저장한다.
- **근거:** 야간 근무(18:00~08:00)처럼 자정을 넘기는 근무의 경우, 근무 시작 일자(월간 그리드 표시용)와 실제 근로시간/야간 근로(22:00~06:00)의 일자별 분할 집계가 서로 상이하므로 두 기준을 엄격히 분리함.

## D-04: 점수 산출의 부동소수점 배제 (Fixed-Point Decimal)
- **결정:** 모든 점수 계산(근무 부담, 오프 경합, 공정성 지수)은 부동소수점(`float`)을 일체 배제하고 `Decimal` 타입을 사용하며, 반올림은 `ROUND_HALF_UP`으로 고정한다.
- **근거:** MASTER_PROMPT §6-4A 요구사항. 반복적인 누적 계산 시 소수점 오차로 인한 순위 역전이나 정합성 훼손 방지.

## D-05: 3가지 점수 지표의 독립적 분리
- **결정:** `work_burden_points`(근무부담, 상한없음), `off_priority_points`(오프경합, 0~94점), `fairness_score`(품질지수, 0~100점)를 단일 숫자로 합치지 않고 별도로 관리한다.
- **근거:** 서로 다른 성격의 가치를 억지로 합산할 경우 발생하는 불투명성을 방지하고, 사용자에게 명확한 판단 근거 제공.

## D-06: 2교대 나이트 연속 근무(N-N)의 처리 방식
- **결정:** 나이트(18:00~익일 08:00) 근무 후 11시간 휴식 규칙(H-REST)을 적용하면 당일 나이트(휴식 10시간) 배정이 불가능하므로, 기본적으로 나이트 다음 날은 오프가 강제된다.
- **근거:** 근로기준법상 보건업 특례 휴식 규정(11시간 연속 휴식)을 보수적으로 반영.

## D-07: 공정성 품질 지수(`fairness_score`)의 N/A 처리
- **결정:** 정책 기준치가 설정되지 않은 지표(예: 피로패턴 상한 미설정 등)는 감점에서 제외(`N/A`)하고, 나머지 구성요소의 가중치를 100% 기준으로 비례 재조정한다.
- **근거:** 미설정된 임의의 값을 0점 감점 처리하여 전체 점수를 왜곡하는 현상 방지.

## D-08: 개인정보 최소 수집 및 컬럼 배제
- **결정:** 주민등록번호, 민감한 질병명, 환자 정보는 DB 테이블에 컬럼 자체를 생성하지 않으며, CSV 일괄 등록 시 주민번호 패턴 탐지 시 업로드를 차단한다.
- **근거:** 의료법 및 개인정보보호법 준수, 프라이버시 사고 원천 차단.

## D-09: 외부 알림 및 프로덕션 데이터 격리
- **결정:** 개발 단계에서는 실제 문자/카카오톡/이메일 발송을 하지 않으며, 인앱 알림(`notifications` 테이블)으로만 시뮬레이션한다.
- **근거:** 사용자 명시적 승인 없는 외부 전송 금지 원칙 준수.

## D-10: 외부 스킬 설치 및 보안 실행 방침
- **결정:** 6개 지정 스킬을 로컬(`.agents/skills/`)에 설치하되, 바이너리 다운로드나 임의 실행은 배제하고 정적 가이드라인 및 로컬 Python 스크립트만 검증 후 사용한다.
- **근거:** MASTER_PROMPT §2 출처 모호한 실행 파일 무검증 실행 금지 원칙 준수.
