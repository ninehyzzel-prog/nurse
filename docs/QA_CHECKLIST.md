## 1. 필수 정량 수치 단위 테스트 (Must Pass)

모든 수치 검증은 부동소수점 오차 없는 `Decimal` 기반 계산 단위 테스트(`backend/tests/test_scoring.py`)로 자동화한다.

### QA-SCORE-01: 근무 부담 점수 26.5점 검증
- **시나리오:** 단일 간호사 월 16회 배정
  - 평일 D 8회: $8 \times 1.0 = 8.0$
  - 평일 N 5회: $5 \times 2.0 = 10.0$
  - 주말 시작 N 2회: $2 \times (2.0 + 1.0) = 6.0$
  - 공휴일 시작 D 1회: $1 \times (1.0 + 1.5) = 2.5$
- **기대 결과:** 정확히 `26.50`점. 
- **추가 검증:** `base_shift_points=18.0`, `weekend_bonus=2.0`, `holiday_bonus=1.5` 분리 반환 확인.

### QA-SCORE-02: OFF 경합 점수 A=35점, B=26점 검증
- **시나리오:** 동일 토요일 일반 희망 OFF 경합 발생
  - 간호사 A: 최근 3개월 주말 부족 2회, 미반영 1회, 정규화 부담 초과 7%, 중요 아님
    $$\min(40, 10 \times 2) + \min(24, 8 \times 1) + \text{clamp}(7, 0, 20) + 0 = 20 + 8 + 7 + 0 = 35.0$$
  - 간호사 B: 주말 부족 0회, 미반영 2회, 정규화 부담 초과 0%, 중요 요청 설정
    $$0 + \min(24, 8 \times 2) + 0 + 10 = 0 + 16 + 0 + 10 = 26.0$$
- **기대 결과:** A의 경합 우선순위 점수 `35.00`, B의 점수 `26.00`. A 우선 검토 판정.

### QA-SCORE-03: 주말 및 공휴일 중복 날짜 가산 검증
- **시나리오:** 일요일이면서 동시에 신정 공휴일인 날에 D 근무(1.0점)를 시작함.
- **기대 결과:**
  - `stack_mode = 'MAX'` (기본): 주말 가산(+1.0)과 공휴일 가산(+1.5) 중 큰 값인 `+1.5`만 적용 $\rightarrow$ 총 2.5점.
  - `stack_mode = 'SUM'` (설정 변경 시): $1.0 + 1.0 + 1.5 = 3.5$점.

### QA-SCORE-04: 점수 상한 및 3개월 롤링 만료 검증
- **시나리오:** 주말 부족 5회(50점 상당), 미반영 4회(32점 상당), 부담 초과 30% 발생.
- **기대 결과:** 상한 룰 적용 확인
  - 주말 부족: $\min(40, 50) = 40$
  - 미반영: $\min(24, 32) = 24$
  - 부담 초과: $\text{clamp}(30, 0, 20) = 20$
  - 중요 요청(10점) 미포함 시 최대 84점, 포함 시 94점 초과 불가.
  - 3개월이 경과한 이월분 레코드는 `expires_at` 도달 시 0점으로 자동 만료.

### QA-SCORE-05: 신규 입사자 중립 기대값 (`insufficient_history`) 검증
- **시나리오:** 입사 1개월 미만 간호사 F의 오프 경합 및 공정성 지표 계산.
- **기대 결과:** 과거 부족/미반영 점수 0점 처리, UI에 "이력 부족(중립값)" 배지 노출, 시스템 오류 없음.

## 2. 도메인 및 시간 경계 테스트

### QA-TIME-01: 자정 넘는 근무(NIGHT)의 일자별 분할 집계
- **시나리오:** 10월 31일 18:00 ~ 11월 1일 08:00 나이트 배정 (휴게 60분은 심야 01:00~02:00 부여)
- **기대 결과:**
  - 근무 배정(Assignment)은 시작일인 10월 31일자로 1회 집계.
  - 10월 31일 실근로시간: 18:00 ~ 24:00 (6시간).
  - 11월 1일 실근로시간: 00:00 ~ 08:00 중 휴게 1시간 차감 $\rightarrow$ 7시간.
  - 야간 근로(22:00 ~ 06:00) 8시간 중 10월 31일에 2시간, 11월 1일에 6시간(휴게시간 고려) 분할 집계.

### QA-TIME-02: 전월 말-당월 초 경계월 연속 근무 및 휴식 검증
- **시나리오:** 전월 10월 31일에 N(18~08)을 근무한 간호사에게 11월 1일 D(08~18) 배정 시도.
- **기대 결과:** 11월 1일 08:00 종료 후 08:00 시작으로 휴식 0시간 $\rightarrow$ H-REST(최소 11시간) 위반으로 솔버 배정 차단 또는 수동 편집 시 즉시 하드 에러 발생.

### QA-TIME-03: 2교대 $\rightarrow$ 3교대 정책 전환 및 과거 확정본 불변 검증
- **시나리오:** 11월에 정책 버전 v2 발행 (EVENING 14:00~23:00 추가).
- **기대 결과:**
  - 과거 10월 확정 근무표(v1) 조회 시 2교대(D/N) 기준 및 당시 점수 유지.
  - 11월 근무표 편성 시에만 3교대 템플릿 정상 동작.

## 3. 제약 최적화 솔버 (OR-Tools) 기능 검증

### QA-SOL-01: 정상 규모 편성 성공 (FEASIBLE)
- **시나리오:** 간호사 6명, 30일, 커버리지 Day 1명 / Night 1명, 휴식 11시간, 희망 오프 12건.
- **기대 결과:** 10초 이내 최적화 완료, `status=FEASIBLE` 또는 `OPTIMAL`, 모든 하드 제약(11시간 휴식, 연속근무 5일 이하) 100% 준수, 후보안 2~3개 도출.

### QA-SOL-02: 인력 부족 상황의 불가 진단 (INFEASIBLE Diagnostics)
- **시나리오:** 간호사 6명, 커버리지 Day 2명 / Night 2명 (월 120 인시 요구, 최소 휴식 11시간 적용 시 물리적 불가능).
- **기대 결과:** 
  - 솔버는 임의로 제약을 완화하여 가짜 근무표를 만들지 않고 `status=INFEASIBLE` 반환.
  - 진단 리포트: "인력 커버리지 요구량(일일 4인) 대비 가용 간호사 수(6인)와 법정 휴식(11시간) 규정 충돌로 편성이 불가능합니다."라는 한글 원인 진단 생성.

### QA-SOL-03: 고정(핀) 배정 엄격 준수
- **시나리오:** 간호사 C의 11월 15일 Day 근무를 수간호사가 핀으로 고정.
- **기대 결과:** 솔버가 생성한 모든 후보안에서 11월 15일 C의 근무는 Day로 유지됨.

- **시나리오:** 간호사 A에게 특정일 Night가 배정된 이유 조회.

- **기대 결과:** 다른 동료의 실명, 개인 사유(예: "가족 제사", "병원 진료"), 세부 점수는 API 및 UI에서 일체 조회되지 않음 (마스킹 확인).

## 5. UI/UX 및 웹 표준 검수 (Web Design Guidelines & Impeccable)

### QA-UX-01: 반응형 뷰포트 레이아웃
- **320px (최소 모바일):** 텍스트 깨짐, 가로 스크롤 잘림 없이 일자별 요약 및 하단 시트 정상 작동.
- **390px (표준 모바일):** 터치 타겟 최소 44×44px 확보, 오프 신청 플로우 2단계 정상 완료.
- **768px (태블릿) 및 1280px (PC):** `RosterGrid` 내부 가로 스크롤 컨테이너 작동, 행/열 고정(sticky), 키보드 방향키 셀 포커스 이동 지원.

### QA-UX-02: 색각 이상자 배려 및 라벨 명확성
- **시나리오:** 고대비 모드 및 색맹 시뮬레이션 환경.
- **기대 결과:** 모든 교대 칩(`ShiftCell`)은 색상뿐만 아니라 문자 코드(`D`, `N`)와 텍스트 레이블을 병기하며, WCAG 대비 4.5:1 이상 준수.
